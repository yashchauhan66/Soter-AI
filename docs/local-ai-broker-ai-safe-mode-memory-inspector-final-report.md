# SoterAI Local AI Broker, AI Safe Mode & AI Memory Inspector — Final Report

Date: 2026-07-06
Scope: Phases 0–12 of the Local AI Broker / AI Safe Mode / AI Memory Inspector mission.

## Executive verdict: **PASS**

The three differentiator features are implemented, tested, packaged, and
documented. The prior PASS state is preserved (all earlier tests still green),
no raw code/secrets/prompts/canaries leak into logs, ledger, memory store,
exports, telemetry, or the shipped bundle, and every new surface is covered by
automated and live tests.

## Features built

1. **SoterAI Local AI Broker** (`@soterai/local-ai-broker`, `apps/local-ai-broker`)
   - Loopback-only (`127.0.0.1`) authenticated Node/TypeScript HTTP service, default port `47321`.
   - Bearer-token auth (≥32 chars) required on every endpoint except `/health`.
   - Strict CORS (disabled), origin rejection, 1 MB body limit, per-minute rate
     limit, request timeout, security headers (`CSP default-src 'none'`, `nosniff`,
     `no-store`, `no-referrer`), and structured safe errors.
   - OpenAI-compatible and Anthropic-compatible scanning proxies with BYOK.
   - Request scan → decision → forward → response scan → leak detection pipeline.
   - In-memory session store, event ring buffer (redacted), approval store.
2. **AI Safe Mode** (`guard-core/SafeMode.ts`)
   - Three levels — Developer (13 rules), Strict (13 rules), Enterprise
     (14 rules, fail-closed) — generated policy applied to scans, context builder,
     and broker request/response evaluation.
3. **AI Memory Inspector** (`guard-core/MemorySession.ts` + extension UI)
   - Session model tracking source, files seen/blocked, decisions, risk
     categories, request/response hashes, canary exposure — redacted-only.

## Broker auth model

- Token generated by the extension (or CLI on first run), stored in VS Code
  SecretStorage and the broker's local secure storage (`~/.soterai/broker/auth-token`).
- Never logged, never exposed to the webview; rotation and clear commands provided.
- All non-`/health` endpoints require `Authorization: Bearer <token>`.

## Local vs cloud data model

- **Local only by default.** No raw request/response is stored. The broker keeps
  request/response **hashes**, risk categories, redacted evidence, decision,
  model/provider name, timestamps, and session id.
- Provider API keys are BYOK, masked, and never logged.
- Cloud policy sync / team rules / redacted events are **disabled by default**.

## Security invariants verified

- Broker binds `127.0.0.1` only; no `0.0.0.0` bind exists in source.
- No unauthenticated protected endpoint; wrong/rotated tokens rejected.
- CORS disabled, foreign origins and `OPTIONS` rejected.
- Body limit, rate limit, timeout, and invalid-JSON handling enforced.
- Safe Mode blocks protected/canary content; canary cannot pass request or response.
- Memory store / export / logs contain no raw secrets, canaries, provider keys, or auth token.

## Known limitations (honest)

- SoterAI can fully inspect/enforce **only** AI traffic routed **through** the
  Local AI Broker or SoterAI-built context. Traffic that bypasses the broker
  (another extension's internal file reads or direct model calls) cannot be
  guaranteed inspected. See `broker-limitations.md`.
- The VS Code extension cannot block every other extension from reading normal
  workspace files; stronger protection requires Protected Vault + Safe Context
  Builder + Local Broker + enterprise policy + future OS/desktop controls.
- Streaming proxy responses are not supported in this MVP (non-stream only).
- Canary-in-request detection requires canaries registered with the broker (the
  extension registers them; the raw CLI relies on secret detectors + Safe Mode).
- **No "100% secure" claim is made.**
