## Stronger protection ke liye architecture badalna padega

### 5. P2 — AI ka environment secrets ke bina

**Main design:** real secrets AI process ke environment mein hon hi nahi. Agent sanitized workspace, dummy data aur narrowly approved operations use kare.

- Original private files, secret history, host home, credential store aur privileged IPC agent ko accessible na hon.
- Windows par real OS identity/VM boundary evaluate karo. Sirf alag process, WSL ya default container ko automatically secure mat maano.
- Agent-writable project policy trusted protection ko relax na kar sake.
- Unmanaged network route aur host mounts available na hon.
- Current Lite ko cooperative mode ke roop mein maintain karo. Stronger mode ka separate scope, installer aur testing ho; Full abhi scaffold hai.

**Done tab:** direct `fs.readFile`, shell/interpreter, alternate path aur independent upload attempts managed secrets access na kar paayen. Useful project work phir bhi ho.

### 6. P2 — secret dene ke bajay approved operation karao

AI bole: “Is approved artifact ko staging par deploy karo.” Trusted broker credential use kare aur deployment ID/status return kare.

Broker mein raw `getSecret`, arbitrary credentialed shell command ya unrestricted authenticated HTTP API na ho. Project/account/resource, destination, operation, artifact digest aur approval expiry bind hon. Allowed domain ke wrong tenant/resource ko bhi reject karo. Raw errors, headers aur production logs AI ko return na karo.

**Important:** AI-modifiable app ko real environment secret de diya to app usse leak kar sakti hai. Output masking ise undo nahi karegi. Local development mein mocks/test identity; sensitive production operations mein trusted service use karo.
