# F09 clarification 03 — private bootstrap attestation before secret release

LOW design review found that an Electron runtime may not honor run-as-Node on every distribution. Strengthen the frozen launch sequence before fixture baseline/source: spawn with the fresh validated OS/locale/temp environment and, for actual Electron only, `ELECTRON_RUN_AS_NODE=1`, but **no selected values** in spawn options. The fixed bootstrap registers STOP/disconnect handlers first and emits `{type:"READY"}` through the child's private IPC. Only after that exact readiness message and a fresh guard does the parent send one `{type:"START",values}` private message. The bootstrap validates the fixed message and sets its own child `process.env` before loading the allowlisted app. These IPC bytes are an explicitly authorized private sink, never output/configuration/audit. No public command accepts IPC/runtime overrides.

The app still receives only selected vault environment variables plus the bounded OS/locale/temp base. Parent `process.env` is unchanged. A runtime that does not execute this bootstrap receives no selected values; timeout/closure/withdrawal withholds the job and requests cooperative stop. START is one-shot. STOP/disconnect before START permanently prevents app load, including while ESM import is pending. STOP aborts the signal and invokes exported stop at most once after module initialization; it never invokes start after cancellation. CommonJS/ESM are loaded with an absolute literal entry and `pathToFileURL` for ESM, with Node argv using the fixed `--` boundary. A normal finite script may run by module initialization; arbitrary app effects cannot be revoked once it is loaded.

Job fixture authors were notified before freeze/execution. API shapes, bounds, output/completion and cooperative stop requirements are unchanged. The chosen actual runtime remains fixed by the coordinator to its own installed `process.execPath`; no executable discovery, new software, separate probe process or normal-profile operation is requested. Actual supported native runtime must demonstrate readiness and app injection in acceptance. Other Electron distributions remain unverified.
