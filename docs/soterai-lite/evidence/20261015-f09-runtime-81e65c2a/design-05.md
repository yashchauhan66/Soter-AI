# F09 clarification 05 — task/debug fixture interfaces, before implementation

`VaultRuntime.run(id:string,signal?:AbortSignal)` accepts an internal cancellation signal. It is not persisted and cannot carry environment overrides; all prior one-argument callers remain valid. Pending native review is invalidated by abort; active owned jobs receive cooperative stop. This is necessary when an owner cancels a task/session before approval resolves.

New `vault-runtime/VaultSurfaces.ts` exports structural `VaultRunCoordinator` with `run(id,signal?)`/`stop(id)`, `VaultTaskTerminal implements vscode.Pseudoterminal` constructor `(runtime:VaultRunCoordinator,descriptorId:string)`, and `VaultDebugAdapter implements vscode.DebugAdapter` with the same constructor. Task `open()` is single-use, `close()` aborts pending requests/stops only its current job. Safe onDidWrite output waits for completion; onDidClose fires only after actual job completion or a failed/cancelled no-job launch. After a 1-second cooperative stop grace, emit a constant waiting message, not a close/completion event. VS Code/user may remove a visible terminal independently; coordinator ownership still persists and is not falsely marked exited.

The inline adapter handles initialize, launch, configurationDone, disconnect and terminate; supportsConfigurationDoneRequest/supportsTerminateRequest=true, no source debugging/evaluation/memory/write capabilities. Unsupported commands fail with a constant response. Launch accepts only the matching descriptorId plus bounded VS Code lifecycle metadata (`type,name,request,noDebug,__sessionId,internalConsoleOptions,__configurationTarget`), no env/program/args. Actual descriptor is constructor-bound; no request-supplied execution code. Initialize emits initialized; run starts once launch and configurationDone both arrive. Terminate/disconnect acknowledge stop request but emit exited/terminated only after actual job completion or no-child launch failure. Output events contain finalized filtered output only. Disposal requests stop; it does not force-kill or convert a live child into an exited session.

These are real owned task/debug lifecycle surfaces, not source-level Node debugging. Their native acceptance must demonstrate actual provider/session events and private application injection on the same final packaged runtime. Synthetic mocks are LOW and are not promoted to native proof.
