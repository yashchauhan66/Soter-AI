# F04 exact one-time safe-read consent

Only F04 is active, after F03 source/evidence commit 3754191788eee4d042f39258ca08e3bbcfaae0ba passed 215 indexed byte hashes/216 exact paths and transition commit 60482bf42c94ce2b9adea76fd54586d8b7446043. No F05 production.

The existing service already binds saved content, regions, policy, workspace and file identity and rereads after approval. Its modal currently describes treatment without previewing the exact safe output, has no recipient binding, and an unanswered confirmation can keep it busy indefinitely. F04 strengthens that same route; no alternate raw read is introduced.

Machine-scope `soterai.lite.safeConsent`, default true and restricted in untrusted workspaces, gates managed safe reads. Withdrawal withholds reads and invalidates owned views; saved restrictions and restriction commands remain available. Shared host-free service decisions are reached only through the flagged command route. The flag never falls back to the old less exact consent.

`AccessReceipt` adds immutable `safeText`, `outputDigest` and `recipient` strings. Build the view from captured region-safe content; dotenv remains names-only/all values masked; marked/recognized sensitive files remain summary-only. Protected-region dotenv remains wholly withheld. No original-content field is added to the receipt. Freeze the receipt; a confirm dependency cannot rewrite the selected output or destination. The native modal receives exactly `safeText` in its `detail` option, avoiding new TextDocuments that other extensions could inspect before approval. Keep the existing explicit one-time button. All output must fit a bounded modal preview (16 KiB UTF-8); larger output is unavailable and releases nothing. File input remains bounded at 64 KiB.

Validate the three declared surfaces at runtime. A trusted dependency may resolve the recipient for `(target,surface)`; otherwise use the fixed internal route label. Caller-supplied command args cannot set approval, recipient, timeout, preview or expiry. Recipient identity is routing metadata, not OS authentication. Bind recipient and surface to the request, check them before/after capture and after confirmation, and compare the recomputed safe-output digest/text after the fresh capture. Any content, region, sensitivity, workspace, policy, file or destination change yields no text.

Use a fixed 60-second request deadline from the start, independent of an unanswered UI or capture. A single owned timer races the operation; revoke/dispose resolves that request as expired immediately. Every request gets a unique monotonic epoch so a late response/capture from an expired request cannot grant or interfere with a newer request. Dispose/finish clears its owned timer/cancel handler. Expiry does not recall data already returned; state this in user documentation. Native stale modals may remain until dismissed, but their responses grant nothing.

Test first with host-free service regressions for exact immutable preview, all-value env masking, protected regions/multiline/malformed/binary/oversize, altered recipient/surface/file/policy/workspace, deadline/unanswered UI, revoke and stale response isolation. Separate native command tests prove `MessageOptions.detail` exactness, machine flag withdrawal, caller args ignored and retained restrictions. Authoring and adversarial review are same-lineage LOW. Preserve every failing baseline before production changes; then focused/full/typecheck/new immutable VSIX/content inspection/current host/affected functional and 17-case baseline/scoped local commit. No catalog promotion or interim rating.
