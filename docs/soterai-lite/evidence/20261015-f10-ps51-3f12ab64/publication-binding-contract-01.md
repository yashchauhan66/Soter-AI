# F10 session publication binding regression contract

Frozen same-lineage LOW regression contract before the new fixture and any matching production fix. Root identified a possible private-binding race between worker filtering/completion and the session's final publication. This contract is a testable concern, not an invented secret-leak result.

The session must revalidate the same private registry/key/cipher binding that authorized its completed output after awaiting worker completion and immediately before publishing that result. Ordinary completion/disposal of the single-use filter is expected and must not itself withhold an unchanged public result. Private binding revocation after successful filter finish but before the worker completion promise resolves must withhold the completed result even when root, source, policy, machine flags and trusted reader are otherwise unchanged. A fresh unrelated registry snapshot must not silently validate output authorized by a now-revoked snapshot.

New `checkedPowerShellPublicationReview.test.ts` uses the real ManagedOutputFilter with an independently controlled private binding and the existing trusted session/workspace stubs. A finite fake worker completes public output filtering while the binding is valid, disposes that single-use sink, then holds its completion promise. Tests explicitly release completion with either unchanged or revoked private binding. The stable control must return COMPLETE with its public output; the revoked control must return WITHHELD with empty channels. No secret is emitted by this fixture, no child/real shell executes, and no leak count is inferred from a binding failure. All synthetic directories are retained.

Root must capture a new failing baseline before source changes, retain any historical package/build, then run the focused pair and affected filter/worker/session controls on the correction. This does not replace exact package/native/full-suite/scoped commit/byte verification or independent/human gates.
