- **Explicit environment replacement:** the pinned local `node_modules/@types/vscode/index.d.ts:12503` provides `TerminalOptions.strictEnv`. Set it true and supply the complete fresh allowlisted public environment. The adjacent API contract says the default also inherits editor environment and `terminal.integrated.env.windows`; passing only a small `env` map without strictEnv does not scrub either source. Test both synthetic ambient and configured terminal variables are absent. Resolve PS5.1 by the reviewed absolute installed executable, not an inherited PATH.
- **Opt-in owned bootstrap:** use a new extension-owned reviewed profile/bootstrap and fixed shell arguments with `-NoProfile`; preserve the user's existing PowerShell profile and other terminal profiles. Configuration changes need exact diff/cancel/backup/conditional undo in synthetic/native acceptance. Restart, workspace/config/flag drift and missing/corrupt owned bootstrap must withdraw managed dispatch rather than silently open an unguarded shell under the managed label.
- **Whole-input declared grammar:** classify a bounded complete input into fixed command variants before any execution. Normalize command case and supported quoting explicitly; reject unsupported operators, chains, expansion, interpolation, scriptblocks, invocation operators, redirection, wildcard semantics, wrappers and encoded commands as a whole. Never approve a regex prefix and then evaluate the original text with Invoke-Expression or an arbitrary `-Command` script. Freeze the accepted grammar and budgets before fixtures.
- **Reuse the existing authority:** read/search/env variants must call F04's exact one-time safe-read service and consume its approved safe output. Do not pass a protected original path to native Get-Content/Select-String or copy the original after obtaining permission for a safe view. Cancel/revoke/timeout/file-policy-root-recipient drift returns no content. Sensitive approval still yields names with masked values. A copy/history/interpreter form outside the grammar should be refused before execution, not transformed into a native bypass.
- **Separate native shell from captured results:** a real terminal/profile is not an output-redaction API. Shell hooks and `onDidStartTerminalShellExecution` supplement checks; the latter runs after execution starts. Checked child output can flow through F08 before publication with bounded completion, stderr and failure handling. Do not claim that the profile or observer filters every byte of arbitrary interactive/native terminal output.
- **Public coding commands need explicit boundaries:** fixed allowlisted argv is preferable to forwarding the caller's original line. A verb such as git/node/python/npm alone is not a safe classification: arguments, project configuration, child app code and dependencies can introduce file reads, hooks or uploads. Supported cases get paired public controls and denied secret-read/chain/one-liner controls. Unsupported native originals, interpreter APIs, direct executable paths, hook removal and independent egress remain disclosed uncovered observations.
- **Bind ownership and minimize evidence:** bind each checked request to its chosen root, terminal/session and current policy/config epoch; closing/cancelling invalidates pending consent. Never accept caller-supplied approved/raw/expiry flags. Do not echo/store original rejected input or secret-bearing command text in terminal history/logs/notifications; use constant failure metadata. Native profile hooks must not weaken the private editor approval route.
- **Safe withdrawal and truthful acceptance:** flag-off removes new managed entrypoints and pending dispatch, retains accepted denies and masked-read rules, and never releases original bytes. Actual PS5.1 profile opt-in/restart/undo and grammar behavior require the exact packaged/native host and actual installed shell; parser mocks alone do not prove that route. UI must say managed checks and disclose arbitrary interactive/native bypasses.

Current ReadTerminal is deliberately a Pseudoterminal reader rather than an OS shell. Preserve its claim while adding a separately named PS5.1 surface. Existing shellExecutionPolicy likewise labels started-command observations MONITORED, not a veto; do not promote it through the new profile.
