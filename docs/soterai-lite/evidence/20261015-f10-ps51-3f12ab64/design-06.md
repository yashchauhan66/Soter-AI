# F10 design 06 — staged Git metadata before fixtures/source

Frozen 16 October 2026 by same-lineage design/test delegate; independence LOW. This extends design02/04 only for the pending GIT route. Production and native acceptance are not implied. No real repository history or original secret is read by these fixtures.

The existing grammar `git status [--short]` means **staged names and change types only** in this checked terminal; `git diff --stat` means **staged diff statistics only**. Every successful result begins `Staged changes only; unstaged and untracked files are not inspected.\n`. Help must disclose these reduced semantics. These commands never show bodies, log/history, unstaged/untracked names, branch/remote/config values, or raw Git diagnostics. Metadata can itself contain registered values and must use the existing complete private F08-compatible filter. Unsupported repositories are visibly withheld; paired ordinary synthetic repositories must succeed.

## Internal API

New `terminal/CheckedGitMetadata.ts` exports `CHECKED_GIT_EXECUTABLE` equal to the already installed standard path `C:\\Program Files\\Git\\cmd\\git.exe`, `supportsCheckedGitVersion(text: unknown): boolean`, and `prepareCheckedGitMetadata(root: string, parentEnvironment: NodeJS.ProcessEnv, enabled: () => boolean): Promise<CheckedGitMetadata | undefined>`. The readonly descriptor has `{executable: string, job: string, environment: NodeJS.ProcessEnv, available(): boolean}`. It is created internally, never accepted from a registered command, parser literal or external request. Its methods and registry guard are not serialized. `supportsCheckedGitVersion` accepts only exact `git version 2.53.0.windows.1` plus its ordinary single line ending; unsupported/unparsed versions refuse. Narrow version support is intentional: a future installed version needs its own review/fixtures, not a download.

Preparation does no child execution. It checks canonical local absolute root and literal pinned Git executable, ordinary non-alias installed file, and captures executable/root/repository metadata identity. It creates a unique retained private empty-config/empty-hooks job directory, using an existing approved synthetic temp root. No delete, Git config write, workspace hook or PATH fallback occurs. `environment` is a fresh minimal `safeGitEnvironment(job, parentEnvironment)`-style map, with no ambient credential/loader/search/config/index/objects/SSH/proxy injection. It additionally fixes `GIT_NO_LAZY_FETCH=1`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, system/global attributes/config and HOME paths to the empty job, `GIT_CONFIG_SYSTEM` to the empty file, and `GIT_PROTOCOL_FROM_USER=0`. No inherited environment merge occurs. The descriptor is immutable; `available()` is sticky false after any observed cancellation, exception, identity or metadata drift. Its serialized form must not expose config contents, hashes or original values.

Preparation admits only an ordinary in-root `.git` directory, ordinary bounded valid UTF8 `HEAD` and local `config`, ordinary object/ref directories, and supported ordinary index/object metadata. Refuse gitfiles/external gitdirs/bare/linked worktrees/commondir/config.worktree, alternate object stores (`objects/info/alternates` and `http-alternates`), partial/promisor config and `.promisor` packs, unknown repository-format extensions, grafts/replacements, sparse/split indexes, aliases/reparse ancestors/hardlinked metadata, malformed/unbounded configuration or metadata. The bounded local-config parser must reject include/includeIf and unsupported syntax before any repository Git execution; it never follows include paths. Accepted keys must be an explicit finite allowlist, with dangerous but deliberately disabled hook/fsmonitor/filter/diff/textconv/credential test entries allowed only where the fixed controls below neutralize their operation. Reject `core.worktree`, alternate object/config indirection and unknown execution-affecting configuration. Metadata observations must be repeated by `available()` before spawn, protocol delivery, during output and final release. Do not recursively read object bodies or history in Node.

Extend `PowerShell51Worker`'s private options with optional `git?: CheckedGitMetadata`, and its operation type to PUBLIC or GIT. PUBLIC remains unchanged. A GIT operation without a prepared live descriptor is BLOCKED before spawn. GIT validation accepts exactly `{kind:'GIT',action:'status'|'diff-stat'}` with no accessors, extra fields, arbitrary args/executable/env. The worker keeps the descriptor private, uses its minimal Git environment for that finite PowerShell worker, and combines descriptor.available with the existing live guard. A forged structural object must be refused: descriptor preparation owns a private brand/registry. No helper from `createSafeGit().run` is called.

The same fixed PowerShell script consumes the GIT request as data. It runs the pinned executable `--version` and requires the exact supported version before any repository operation. Then it invokes one fixed argv vector (never Evaluate/Invoke-Expression or a caller string), with hardened existing SafeGit argument prefix plus `--no-lazy-fetch`, `--no-replace-objects`, `--no-optional-locks`, `-c core.pager=`, `-c color.ui=false`, `-c diff.external=`, `-c core.attributesFile=<empty file>`, and `-c protocol.allow=never`. Repository path is fixed to the captured root; no revision/path override. Operation suffix is `diff --cached --name-status --no-renames --no-ext-diff --no-textconv --ignore-submodules=all --` or `diff --cached --stat --no-renames --no-ext-diff --no-textconv --ignore-submodules=all --`. Git nonzero/errors withhold all output including label and diagnostics. `status` uses Git's default path quoting, not NUL bytes unsupported by F08. No normal worktree `status`, fallback/body/history/fetch/network command runs.

The PS child waits for its own Git invocation naturally. Cancellation/timeout/overflow only abandons output and preserves actual PS close/drained-pipe ownership; no kill, Stop-Process, force-exit, execFile timeout or maxBuffer termination. The existing F10 worker ownership behavior applies to Git's descendant too: parent PS alive means STOP_UNCONFIRMED, never guessed completion. The fixed worker's ordinary error result is not process termination.

Dispatcher GIT branch prepares its own descriptor before the output filter, then passes it only to its worker factory, using the same single operation/global admission bound. Every completion passes the same private registry guard/F08 output; a drifted descriptor is WITHHELD. No real source file enters the worker.

## Fixture gates

New `checkedGitMetadata.test.ts` freezes descriptor/version/environment/repository/drift refusal controls and mocked worker protocol/output/lifecycle checks. New `checkedGitMetadataActual.test.ts` uses only retained synthetic repositories and the actual installed Git and PS worker. Synthetic setup may invoke pinned Git only through a finite no-timeout spawn which waits for actual close, with command-local empty hooks/config and no remote/network. No fixture cleans up its inputs or jobs. Staged public controls must succeed; an unstaged-only sentinel and untracked-only sentinel must be absent; known registered filename metadata must mask; configured hooks/fsmonitor/filter/external-diff/textconv/credential helpers must leave their synthetic marker absent; included/partial/promisor/alternate/missing-object cases must withhold without callback or network fallback. Cancellation/withdrawal remains sticky and no fixture kills a process. All raw receipts and failed baselines are retained. Native extension UI/exact VSIX registration is root acceptance work, not promoted by unit tests.

## Primary source basis and limits

Installed metadata probe: literal standard Git `--version` returned `git version 2.53.0.windows.1` (16 October 2026); separate immutable JSON probe receipt records exact command/exit/output. [Git 2.53.0](https://git-scm.com/docs/git/2.53.0) documents `--no-lazy-fetch`, optional locks and replacement controls. [Git diff 2.53.0](https://git-scm.com/docs/git-diff/2.53.0) defines cached comparison against HEAD/index, disabled conversion/external drivers, rename and submodule controls. [Git config 2.53.0](https://git-scm.com/docs/git-config/2.53.0) documents include expansion, which this route rejects before repository invocation. The inference that this finite cached route avoids worktree clean/process filters is checked using synthetic helper markers on the exact installed runtime; it is not a universal callback/confinement guarantee. Only official primary documentation was consulted; no source archive was downloaded.

No arbitrary shell interception, hostile same-user filesystem locking, independent sink, external tool, non-Windows support, human review or final rating is claimed. Missing/corrupt index/object states can fail after safe spawn and remain constant WITHHELD; disabled lazy fetch/protocol prevents a repair attempt. Git's read-only cached statistics still read existing local staged/base blobs internally, which is essential to statistics; no body bytes are released.
