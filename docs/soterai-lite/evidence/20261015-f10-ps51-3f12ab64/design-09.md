# F10 design 09 — fixed empty-tree attributes before regressions/fix

Same-lineage LOW review supplement to design06/07/08, frozen before the matching new attribute regressions and production fix. The retained existing module admits `.git/info/attributes` and a canonicality-unchecked `.git/info` directory; the current fixed cached Git command has no explicit attribute source. This supplement tightens the finite metadata route without introducing body/history/network fallback.

Every actual cached metadata operation adds fixed global option `--attr-source=4b825dc642cb6eb9a060e54bf8d69288fbee4904`, the SHA1 empty tree. This treats all custom worktree/index/committed `.gitattributes` as irrelevant to this limited numeric/name metadata route and avoids reading them for attributes. Stats deliberately use default textual/binary detection, not repository custom diff attributes. This additional semantics belongs in help/reporting. Existing strict repositoryformatversion=0/SHA1 admission remains; no caller source/revision override, object write or alternate object store is added.

The node preflight rejects any `.git/info/attributes` entry, ordinary or alias, before its body is read. If `.git/info` exists, validate its canonical ordinary directory identity before listing names or examining children; aliases/junctions (including an empty external target) withhold. Bound its names and refuse grafts/attributes case-insensitively. `available()` observes absence and canonical directory identity continuously and remains sticky on change. The public worker still uses the existing empty system/global attribute controls and fixed no-textconv/no-ext-diff/no-renames/ignore-submodules options.

Primary-source basis: [Git 2.53.0 global options](https://git-scm.com/docs/git/2.53.0) documents `--attr-source`. [Git v2.53.0 attr.c](https://raw.githubusercontent.com/git/git/v2.53.0/attr.c) reads `.git/info/attributes` independently in `bootstrap_attr_stack`; the source also resolves an explicit attribute source to a tree. [Git v2.53.0 odb.c](https://raw.githubusercontent.com/git/git/v2.53.0/odb.c) `find_cached_object` supplies the hash algorithm's virtual empty tree without requiring a physical object. Inferring unborn compatibility from that source is not an execution PASS: the new exact installed-runtime empty-tree fixture must establish it before acceptance. If that experiment fails, preserve its result and revise the contract before implementation; do not silently create an object or fall back to worktree attributes.

New `checkedGitMetadataAttributes.test.ts` freezes paired ordinary/alias/attribute-presence/drift checks, an exact pinned Git experiment on a synthetic unborn repository with no empty-tree object file, and actual worker stats with an unstaged `*.txt -diff` attribute override. The latter must still report default insertion counts, providing a behavioral difference from the old worktree-attribute path. All setup is retained, finite, synthetic, offline and kill-free. The node-only refusals and worker behavioral fixture must get fresh baseline evidence before source is changed. No claim of OS confinement, hostile filesystem atomicity, independent/human verification or final rating is made.
