# F06 frozen implementation contract

F05 source/evidence fd73041ad2d773a9c259c69e20e48245e51487ea and transition 227b37372310a5a59510cfbafd55187ea17fcbb5 passed their byte barriers. F06 alone is active. These are scoped cooperative IDE controls, not protection from arbitrary same-user software. No numerical rating yet.

1. Add machine/restricted `soterai.lite.vaultMode`, default true. Migration remains optional and always requires a native owner confirmation. The flag enables availability, never automatic migration. All manager mutation methods enforce trust, local workspace binding and this flag themselves. Cancellation writes nothing. Restore methods require their own explicit native warning that raw secrets will become readable in the project.
2. `VaultMigrationPlan.ts` exports `createVaultMigrationPlan(text, environment, generation)` returning private `{maskedText, exampleText, candidates}`. Candidates use existing VaultCandidate fields; their raw values stay private. Environment parsing reuses SecureEditorModel to correctly include quoted multiline/duplicate fields. Unsupported syntax is withheld. Placeholders contain the generation and field ordinal to prevent cross-file collisions. Examples contain unique assignment names with empty values only, no copied comments, suffixes, unsupported lines or multiline contents. Preview always uses the constant `MASKED`; no value prefix, suffix, length or value hash is exposed.
3. Preserve VaultManager public signatures `preview`, `migrate`, `restore`, `restoreFromBackup`, `writeEnvExample`, `status`, `knownPlaceholders`. Add `recoverMigration(uri): Promise<boolean>`. `migrate` owns its metadata-only native review, so watcher/auto-migration calls cannot bypass it. Existing command review is removed in favor of that review. Recovery gets a separate safe-completion review. Explicit plaintext restoration is a separate disclosure action and never automatic rollback.
4. Verify SecretStorage get/store/get equality and 32-byte canonical key format before any workspace mutation. An existing encrypted vault/checkpoint with missing or invalid key is withheld, never regenerated or replaced by an empty vault. Report API availability honestly; OS key custody is not certified. No plaintext fallback. Existing v1 encrypted entries are preserved; new v2 entries bind absolute source and root URIs. Legacy relative entries cannot be restored automatically into another project.
5. Serialize mutations and acquire an exclusive extension-global-storage lock before key creation/read-modify-write. Live or uncertain lock ownership is withheld. Only provably dead process ownership permits stale-lock recovery, with no process termination. Validate canonical local storage outside the project, reject aliases/hardlinks, enforce bounded regular-file reads (source 64 KiB, encrypted store/checkpoints bounded). Reject dirty/open stale source editors. Do not create a source TextDocument or plaintext sibling backup.
6. Durable encrypted generation checkpoints outside the workspace record exact source/root, original and masked text, safe example, and encrypted vault before/after images. Immutable generation data is written and read back before destructive work. A deterministic per-source pointer refers to an issued generation. Strict validation, source/root binding and authenticated ciphertext reject swapped/tampered records. Stages: checkpoint -> encrypted vault -> placeholders -> safe example -> completed receipt. At each step reread binding/content and verify writes. Failures preserve encrypted recovery and never silently restore plaintext. Examples use exclusive creation or an exact identical existing example; conflicting existing files are not overwritten.
7. `recoverMigration` resumes only the issued generation and only recognized pre/post source and vault states; conflicting external edits, missing keys, malformed data or aliases are withheld. It completes the masked outcome without disclosing originals. Restart/idempotence and cross-window concurrency must be tested. Backups retain source binding; raw restoration needs fresh explicit disclosure approval and file drift checks.
8. Test authoring may run in parallel, production implementation remains root only. First execute failing synthetic baseline, then focused tests and typecheck, matching complete suite, exact new VSIX inspection, actual current native host/restart and affected functional/security hosts, scoped local commit and byte verification. All failures and command receipts are immutable. Existing F01-F05 denies/masking/revocation remain regression controls. Feature F07 cannot start until this barrier passes.

Minimum synthetic cases: constant preview; multiline/duplicates and unsupported syntax; example comments never copied; cancellation; missing/mismatched store; flag withdrawal and untrusted/remote resources; source drift during review/store; dirty editors; source/vault/example failures; encrypted checkpoint recover/restart; idempotence; conflicting example; source/root swapped backup; corrupt vault/checkpoint; no silent plaintext rollback; concurrency. Native availability and actual SecretStorage API use do not prove independent human presence or OS custody. Test-only scripted native owner responses are LOW independence.
