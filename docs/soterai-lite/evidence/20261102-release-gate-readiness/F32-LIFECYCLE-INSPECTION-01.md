## Minimal safe aggregate design

Expose one visible **SoterAI: Restore changes before removal** command, backed by a small lifecycle coordinator with a fixed code-owned adapter list, not user-provided paths, command IDs, globs, script text or a search for names containing `restore`. The coordinator reads only bounded receipt metadata and offers actions for the currently selected local owner project/profile. A corrupt, foreign-root, unknown-version or ambiguous receipt is a pending issue, never "nothing to restore". Do not enumerate/decrypt arbitrary backup stores or vendor config on activation.

The initial summary states that routing will become Uncovered, prior policy/ciphertext stays, external tools should be closed normally, and uninstall will not finish recovery. The user selects each pending operation; the existing per-route diff/modal/chooser remains the final write authority. No aggregate answer substitutes for a transaction's fresh confirmation. Do not pass approval booleans or restore authority through executeCommand arguments. Serial execution is appropriate: simultaneous config edits would invalidate snapshots and make partial recovery hard to explain.

Normalize only explicit documented terminal statuses: terminal/association SAVED -> RESTORED; adapter/hook/profile RESTORED -> RESTORED; CANCELLED -> CANCELLED; CHANGED/INCOMPLETE/FAILED/UNAVAILABLE/malformed/undefined/thrown -> INCOMPLETE with a fixed safe reason. A missing receipt yields NOT_APPLICABLE only after a read-only adapter confirms absence; generic status UNAVAILABLE does not prove no owned changes exist. Re-read receipt absence and owned-setting postconditions after successful transactions. Preserve incomplete receipts. A later operation failing must not re-apply an already removed route or declare total rollback. The summary reports restored/pending/cancelled counts and concrete next steps, with no file contents or original credential values.

Use existing narrowly scoped stop functions only after owned restore transactions no longer need live services: `stopChecked{PowerShell,Cmd,GitBash}`, `stopVaultRuntime`, reference revocation/clear, and `BrokerManager.stop()`. Call the broker stop through a typed service dependency or existing `soterai.stopLocalAIBroker` command, whose result is an `OwnedBrokerSnapshot`. A STOP_UNCONFIRMED result remains INCOMPLETE and blocks a "safe to remove" success message; do not send signals or launch a replacement. Shutdown invalidation must not accidentally disable a still-pending restore transaction.

If the product requirement includes restore with its route flag off, the smallest reviewed extension is a **separate restore-only availability lease** in the existing terminal/association/Cline/Claude adapter, retaining trusted local owner, path/identity/receipt checks. It must not re-enable content release/setup or bypass unsupported runtime/path checks. This is production behavior needing tests; the aggregate alone cannot fix it. Alternatively report the unavailable owned route explicitly and document recovery before withdrawal, without claiming comprehensive removal completion.

Upgrade reconciliation is metadata-only and conservative: retain identity `soterai.soterai-ide-guard`, policy/storage keys, existing ciphertext and receipts; recognize old known receipt schemas, surface PREPARED/partial recovery, and treat old PID/session records as UNVERIFIED. Do not resume a previously healthy route, replay an old approval, assume a prior process exited, overwrite modified files, auto-migrate to plaintext, or clean unknown state. Unknown policy schema must withhold managed reads. No uninstall callback is assumed: the explicit command runs **before** disable/removal; docs cover reinstallation of the exact package into the same isolated profile to use retained recovery state.

## Meaningful new component cases (all NOT_RUN)

1. No receipts: typed NOT_APPLICABLE, no commands/writes, no decrypt, policy/ciphertext untouched; forged/corrupt receipt instead yields INCOMPLETE.
2. One eligible terminal or association restore: preserve unrelated settings, undefined versus null and exact target; post-write mismatch retains INCOMPLETE. With multiple roots, only the confirmed owner can be affected.
3. Modified owned entry, changed root/trust/flag/receipt while modal open, double command and disposed coordinator: no unintended write and no blanket success.
4. Cancellation at summary or transaction modal writes nothing new; cancel after a prior success preserves that success and reports remaining actions.
5. Mixed route results including thrown/void/unrecognized/UNAVAILABLE/CHANGED: conservative per-operation result, retained receipts, overall INCOMPLETE; no "all restored" message.
6. Command registry includes only the reviewed allowlist. Assert no vault/raw-backup/legacy auto-config disclosure command is executed and no caller argument supplies a path/approval/action ID.
7. Dedicated profile undo removes exact owned absent-before config only; unrelated files and policy survive; changed owned file refuses. Restart resumes recovery metadata, not routing authority.
8. Broker stop: stop+close+stdoutEOF+stderrEOF yields stopped; exit-only, close without EOF, missing stop acknowledgement or bounded timeout stays STOP_UNCONFIRMED. No process signal and no replacement launch.
9. Upgrade with current, legacy, PREPARED, corrupt and unknown receipts/policy schemas: preserve old bytes, retain denies/ciphertext, revoke stale session approvals, report safe recovery. Rollback/disable does not restore weak raw paths.

Reuse assertions from `checkedPowerShellProfile.test.ts`, `checkedCmdProfile.test.ts`, `checkedGitBashProfile.test.ts`, `lite-secure-editor-commands.test.ts`, all five `*AdapterLifecycle.test.ts`, `historyProfileTransaction{,.integration}.test.ts`, `preCommitHookRestore.test.ts`, `prePushHookRestore.test.ts`, `ownedBrokerLifecycle.test.ts`, `ownedBrokerManager.test.ts`, and `lite-versioned-policy*.test.ts`. Add coordinator tests that prove these interactions rather than retest every transaction's implementation.
