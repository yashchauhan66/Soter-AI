# F05 contract and reliability review additions

Same-lineage read-only design review LOW identified save-revision locking, recovery after partial original corruption, and cross-window recovery-key replacement. Freeze these before production; original design-01 remains.

Model metadata is exactly deep-frozen `{revision:number, fields:[{id:string,name:string,editable:boolean}]}`. Revision is a monotonic safe integer, not a published plaintext digest. Unsupported dotenv syntax yields one Contents field with editable=false; non-env marked-sensitive text uses one editable Contents field. Owner reads support conventional double-quoted newline/carriage-return escapes and literal single/backtick quoting without interpolation; edits choose a supported literal representation or fail without mutation. Client protocol is `{type:'reveal'|'edit'|'hide',session:string,revision:number,field:string}`; data-session/data-revision/data-field are masked UI metadata. New edit values come from a native password input, never forged message values.

Document revision is locked through candidate edits, encrypted recovery and save I/O. Busy mutations/undo/redo/second saves fail or await the same documented owner operation; a promise must never let VS Code mark a newer unwritten draft clean. Dirty external changes never silently replace the saved basis. Add a pause-save/revision regression.

Authenticated recovery opens from issued encrypted backup even when this provider's interrupted in-place save left the original invalid UTF-8 or with a changed digest. Canonical workspace/root/regular-file/no-alias guards still apply, but restoring a private draft must not first decode the corrupted original. Restore itself never overwrites disk. A recovered conflicting original requires fresh native owner review before saving and another identity/binding check; cancellation keeps encrypted recovery and dirty state.

Never use one overwritten fixed recovery key across windows. Every recovery generation gets a unique UUID-scoped SecretStorage key, verified by store/get and retained while its issued ciphertext exists. Each issued record contains only id/source/root/ciphertext hash and a strict-prefix key id, never the key or values. Authenticate the generation-specific key id in the recovery envelope/AAD; wrong/mismatched key ids fail. Two windows cannot overwrite each other's generation. A bounded in-process queue still handles split views and metadata writes. Delete only the exact issued ciphertext/key when its own backup is released, and retain records on failed cleanup.

Recovery primitive contract remains encryptEditorRecovery(payload,key) and decryptEditorRecovery(envelope,key,{source,root}) for the base six-field envelope; provider may supply optional authenticated keyId binding. Plain payload is exact `{schemaVersion:1,source,root,savedText,draftText,fileIdentity}`, each text64KiB max; base envelope has schemaVersion/source/root/nonce/ciphertext/tag, optionally authenticated keyId for the provider. Strict duplicate JSON header rejection, canonical base64,12-byte nonce/16-byte tag/32-byte key, bounded512KiB envelope. No plaintext disk fallback.

Association operations target only the chosen project's configuration: workspace target for one folder, folder target for multi-root. Native diff/approval/receipt undo must preserve unrelated associations and refuse third-party changes. No global editor setting mutation.
