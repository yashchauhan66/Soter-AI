## Existing hook scaffold: preserve baseline, then test the actual gaps

`packages/vscode-extension/src/scanners/continuousGuards.ts:50` has `parseGitHooksPath`; `buildPreCommitHook` starts at78; `soterai.installGitSecretHook` starts around232; `soterai.copyPreCommitHookScript` follows. Tests are in `src/__tests__/continuous-guards.test.ts` (simple presence/parser examples).

Observed source limitations, not newly executed failures:

1. Generated shell script performs `DIFF=$(git diff --cached --unified=0 2>/dev/null || true)` and a duplicated `grep` pattern set. A Git failure is converted into apparent clean success. It relies on ambient `git`/`grep` and does not use the canonical matcher, fixed content grammar or byte/work budgets.
2. Local `.git/config` parsing returns the first simple hooksPath and treats unreadable config as absent. Effective global/conditional/environment/per-command hook configuration, duplicate keys, gitdir files/worktrees and ambiguity are not validated. Installing `.git/hooks/pre-commit` is not proof that an owner commit will execute it.
3. Installer uses the first workspace, creates `.git/hooks`, recognizes ownership by marker substring, writes an unencrypted `pre-commit.soterai-backup` sibling and replaces the hook. No bounded diff, durable guarded recovery receipt, drift check or reviewable undo is present in this route. Raw caught errors are interpolated into UI.
4. This source does not expose the F26 opt-in flag family. Existing command registration/scaffold and tests are not F26 acceptance. Baseline tests should preserve these exact before-behavior facts before any replacement integration changes.

## Concrete test-first oracles for the future F26a card

These are proposed checks, all **NOT-RUN**. Final supported grammar/budgets/entry-point authority must be made concrete on the existing card before implementation; do not borrow a past PASS.

- **Opt-in and review:** absent/default-disabled owner flag makes no hook/runtime/config/backup write. Repository enable cannot override owner false. Cancelled preview leaves exact repo/config/index/hooks, editor state and key-store counts unchanged. Caller `approved/path/root/script/content` arguments cannot authorize or redirect install/restore. Busy, disposal, trust/root/policy/flag changes and disable-then-reenable withdraw the pending single-use plan.
- **Effective coexistence:** test ordinary default hooks plus relative/absolute custom hooksPath, paths with spaces, duplicate local keys, synthetic global/include/includeIf config, environment/per-command override ambiguity and existing Husky/Lefthook-style fixtures. Each branch either executes the actual reviewed owner route or clearly refuses without writing a dead hook/config override. Never silently reset persistent hooksPath or bypass an existing hook. A supported chain preserves original invocation/exit semantics; an unsupported chain leaves all existing bytes untouched.
- **Ownership and reversible writes:** byte-exact original existing hook containing a synthetic canary; forged marker, stale generation, changed hook after preview, concurrent new hook creation, prior backup collision, wrong/corrupt/missing backup/key, failed PREPARED persistence, write/readback/rename/mode/receipt failure. Fail before replacement when backup is unavailable. Verify encrypted private recovery precedes mutation. Undo only the unchanged owned generation, restoring original bytes/absence and applicable mode; owner edits or new files remain intact. Remove/review restore withdraws coverage immediately; crash/restart reconciliation never reports INSTALLED from a PREPARED receipt alone.
- **Staged content, not worktree substitution:** secret staged then worktree sanitized must block; public staged then unstaged secret must pass without scanning the unstaged secret as if committed. Whole supported staged blob is the positive enforcement authority, not only pretty diff lines: static multiline/escaped source, renamed/copy fixtures, additions, zero-byte files and initial commit. Include `commit -a` and path-limited commit controls: bind the actual effective index supplied by the owned Git invocation or clearly refuse unsupported alternate/temporary-index modes; never silently scan the default index instead. Deleted-only public change must have a useful control; old deleted content must not be counted as newly committed. Test filenames beginning with `-`, spaces/Unicode/quotes and NUL-delimited protocol; reject malformed lengths/types/paths/index formats rather than shell-parse names. No source file execution, filters/textconv/ext-diff/fsmonitor/credential helper, reference resolution or network lazy fetch.
- **Canonical detection and useful controls:** same canary tested through the existing canonical analyzer/matcher and hook route; raw and declared one-layer encodings, low-entropy registered value with an actual pre-registration heuristic-negative control, supported sensitive static assignments, provider canaries; template placeholders, public/publishable keys, public constants/stack text/near-matches stay useful. Keep per-file framing; no phantom matches from joining unrelated paths, JSON framing or unrelated files. Do not imply a live registry where standalone authority is unavailable.
- **Failures and limits:** fix numeric caps for file count plus sentinel, each blob, total unique raw bytes, parse/work/match count, stderr/output and elapsed time. At exact bound public content succeeds; next unit withholds/refuses. Invalid UTF8/binary/unsupported syntax/submodule/unmerged/index entries must be explicit partial/refusal, never an all-clear or dropped secret. Charge raw admission even when decoding fails. Nonzero Git, truncated protocol, stream errors, monotonic reversal/expiry, source/index/config/runtime mutation and missing tool must withhold without raw stderr/value/path exposure. Final revalidation must bind the result to the staged index actually about to be committed.
- **Native isolated repository positive oracle:** retain a new marked synthetic repository/profile, pinned Git/runtime/hook/script digests and active configuration witness. Install through actual packaged owner command and review diff; an actual public commit must advance HEAD and create the expected public tree while an existing synthetic hook writes its harmless invocation marker. Actual blocked-secret commit must exit nonzero, keep HEAD unchanged and retain staged bytes without rewriting the worktree/index or printing values. Assert actual hook marker/owned scanner invocation so empty-hooks or a wrapper refusing before hook launch cannot false-PASS the negative control. Compare whole synthetic repository allowlisted before/after changes, and exercise restart/restore plus another public commit after restored existing hook. No source TextDocument or original hook preview in a normal editor.
- **Child and sink evidence:** every owned Git/scanner/setup child uses absolute pinned executable, literal args and complete allowlisted environment; synthetic ambient canaries absent, no secret in argv/env/files/stdout/stderr/UI/state/export. Capture pre-child parent environment once and compare after every path. Delegated real child must close with both EOFs and no signals, pipe destruction, timeout-kill or exit inference from wrapper absence. Withdrawal may return an unavailable result while ownership remains explicitly STOP_UNCONFIRMED; preserve busy ownership until actual closure. Hold a genuinely releasable completed decision and mutate authority before final sink to test the release guard; do not infer this race from a different early refusal.

## Scope and pending decisions

Hook dispatch is cooperative. `--no-verify`, deleting/changing hooks, owner per-command configuration overrides, independent native Git/object reads, other collectors/uploads and prior commits stay outside its protection claim. No history rewrite, credential rotation, universal masking or operating-system boundary is inferred. Windows installed Git/runtime only may be supported after actual evidence; other platforms, custom repository layouts and unknown transformations require explicit unsupported/NOT_TESTED treatment.

Before future production, the card still needs a bounded staged-object protocol and standalone scanner/runtime/config/registry authority, an honest disabled/uninstalled lifecycle, and a coexistence policy for effective owner hook configuration. Read-only scanner isolation and actual owner-hook execution must remain distinct authorities: automatically adding the existing empty-hooks prefix to the positive commit would defeat the feature being tested. No new dependencies/downloads, normal-profile changes, real-secret reads, pushes, publication or tags are authorized by this document.
