# SoterAI — Governance, Bus-Factor & Trust (R9)

**Purpose:** enterprise buyers will not bet on a bus-factor-1 vendor. This page is the standing mitigation — governance, security-response SLA, and continuity — kept in-repo so it cannot silently rot.

## 1. Maintainer & continuity
- **Lead maintainer:** founder (solo today). Continuity plan: code, signing keys, model artifacts, and runbooks live in this repo + offline backup; a named co-maintainer escalation list is maintained off-repo and reviewed quarterly.
- **CLA:** in force (`CLA.md`); all external contributions are CLA-covered so relicensing/transfer is never blocked.
- **Advisory board (forming):** security + compliance advisors invited; names published here once accepted.

## 2. Security-response SLA
| Severity | First response | Containment | Public note |
|---|---|---|---|
| Critical (RCE, auth bypass, license leak) | ≤ 24 h | ≤ 72 h | ≤ 7 days with fix |
| High (guard bypass, detection-evasion) | ≤ 48 h | ≤ 7 days | on fix release |
| Medium / Low | ≤ 7 days | next release cycle | changelog |

Report: see `SECURITY.md`. Coordinated disclosure honoured; reporter credited on request.

## 3. Release & signing policy
- Every model artifact is Ed25519-signed at release; `scripts/ml/sign-model-artifact.ts` re-runs the runtime gate and refuses to emit a manifest the gate would reject.
- Every release notes file links its SHA-256 evidence pack (`artifacts/security/eu-ai-act-evidence-pack.json` regenerated by `scripts/compliance/eu-ai-act-pack.mjs`).

## 4. Change control
- All changes land via PR; CI runs the root `tsx --test` suite + multilingual regression pin + eval scripts; merge blocked on failure.
- Model/config changes additionally require the signing script to re-admit the artifact before merge.

## 5. Honesty registry
`artifacts/security/capabilities.json` (`honest:true`) lists 2 explicit UNSUPPORTED capabilities and per-capability known bypasses. No silent capability claims are permitted; docs must cite a repo path or a measured artifact.
