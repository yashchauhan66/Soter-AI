# Acceptance criteria: future expected-result assertions

**INFERENCE — Status, 2026-10-09.** All assertions below are design requirements and UNTESTED. They are declarative expected results for later authorized verification, not execution procedures, code or reproduction steps.

**INFERENCE — Symbols.** U is the hostile normal USER identity; A/B are separate controller-enrolled workloads/launch epochs; P is the protected editor; S is the controller; C is the confirmation component; E is mandatory networking; J is a constrained helper; D is an offline private workload; V holds protected originals. Y@v is a synthetic protected item/revision; Z is public data. These names are symbolic, not real credentials or filesystem locations.

**INFERENCE — Classification rule.** A future PASS requires the expected secure result and working public/authorized controls for the exact deployed configuration. Protected disclosure or excess authority is FAIL. Unavailable capability, error, missing observation or incomplete evidence is INCOMPLETE; requested but unevaluated combinations are UNTESTED/NOT_TESTED. Preserve the original observation labels in the Phase 0 specification and do not equate harness completion with security PASS.

## Scope, timing and evidence contract

**INFERENCE — G1 acknowledgement.** A01–A06 apply only after independent custody and required enrollment conditions are evidenced. Existing unknown/reachable legacy copies keep acknowledgement pending; this qualification is an open target gap, not permission to issue a broader G1 claim.

**INFERENCE — G2 scope.** Grants default to one item/revision, one operation, one enrolled workload and a 60-second consumption limit. Explicit streaming leases initially cap at five minutes. Whole-workload grants cover its descendants; individual-process scope remains unsupported without independent identity. Correct user presence alone does not substitute for exact scope.

**INFERENCE — G3 persistence.** Authoritative policy, enforcers, store ownership and checkpoints outlive editor lifecycle. A lost authority keeps originals sealed and new operations denied. No default recreation or feature-disable path may relax acknowledged protection.

**INFERENCE — G4 revocation.** tD is the serialized revocation decision; tA acknowledges completed cancellation/drain/enforcement. Initial one-second active-termination objective remains unmeasured. Pre-tD committed effects may already be in flight; no new release after tD is permitted. A19 must expose both decision and enforcement observations.

**INFERENCE — G5 retention.** Separate reference denial, operational lease revocation, retained ciphertext, underlying deletion and downstream credential validity. No deletion claim is based on absence from an in-memory map alone.

**INFERENCE — G6 reporting.** Five-second status validity is a proposed freshness ceiling, not proof of uninterrupted liveness. Show as-of evidence and uncertainty; a receipt cannot certify future behavior. The trusted P/C UI is authoritative; U's editor pixels remain outside the demonstrated boundary.

**INFERENCE — Future evidence fields.** Record immutable run/observation ID, client date, source/bundle/artifact hashes, OS/editor/agent versions, authenticated principal/workload/launch identity, policy/enforcer/witness epochs, fixture item/revision, consent/grant state, observed boundary, expected/actual classification and limitations. Keep failed runs and old bundle evidence intact. Document hashes are review provenance, not an independent operational audit.

**INFERENCE — Current gaps retained.** The Windows token finding, control-token/directory ACL gap, static-only credential/F16 status, C/W feasibility, current native bundle gap and all real-agent/platform coverage remain unresolved. No assertion was executed in Phase 3.
