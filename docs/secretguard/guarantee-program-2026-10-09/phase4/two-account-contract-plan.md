## Scope and authority contract

**INFERENCE — Keep T visible.** The original T includes hostile processes with the user's authority; it is not silently rewritten. This candidate's conditional boundary applies only when all participating untrusted AI tools, extensions, shells, Git helpers, MCP servers and descendants execute as **Agent**, a distinct standard account. **Main** must be treated as trusted. An agent started under Main, or hostile Main-account extension/browser/helper, remains a material full-T gap. Report it as **OUTSIDE CANDIDATE COVERAGE**, not as an excluded attack or a successful G1–G6 result.

| Role/resource | Proposed contract, all INFERENCE |
|---|---|
| Main | Trusted human account and separate interactive session. Holds protected originals, user-scoped secret keys, authoritative policy and approval console. No AI extensions or unreviewed workspace tasks/helpers in the protected editor. |
| Agent | Actual standard account with a separate SID/profile/session; not an administrator with merely a filtered token. Runs the complete untrusted tool/process tree. Holds only explicitly public data and opaque placeholders. |
| Management role | Trusted existing administrative authority outside Agent manages any later machine policy. It is not a third account provisioned by this plan. If Main is already an administrator, Main and management share trust; this does not protect against Main compromise. If no suitable existing authority exists, the management prerequisite is INCOMPLETE. Main's actual account membership has not been re-inspected. |
| Private custody | Main-owned private NTFS-backed objects, keys, policy, recovery data and parent paths with effective access denied to Agent. Review explicit Agent denies and restricted allows by effective token rights; do not deny a broad group that Main itself needs. No inherited foreign read/write authority, writable authority-binary parent, or shared credential/config path. |
| Public workspace | A versioned, explicitly classified representation separated from originals. No private .git objects/history, homes, vaults, backups, recovery files, caches, credential helpers or secret-bearing environment. A shared folder is a publication channel, not private custody. |
| Main editor | Opens private material only in Main's separate session. Editing .env saves a protected revision; Agent retains placeholders. Agent-produced files are data for reviewed import, never a source of executable Main tasks, extensions, hooks or startup configuration. |
| Agent grants | The account and its descendants form one recipient compartment. PID, executable name or caller-supplied session text cannot promise that only one AI tool within Agent can use authority. Agent-only per-process grants are unsupported without further isolation and evidence. |
| Narrow IPC | OS-authenticated cross-account request channel with restrictive object rights. Agent may submit bounded pending requests/public status queries; it receives no Main signing/control credential. Loopback address or a bearer/session string alone is not the identity contract. |

**INFERENCE — Enrollment.** Merely changing the current file ACL is insufficient. ## Consent, policy and revocation contracts

**INFERENCE — Consent.** Agent creates only a rate-limited pending record. The human independently switches to Main's trusted session and opens its console; the request must not activate a privileged approval or signing ceremony. Main generates authoritative labels and shows item/region/key and revision/hash, operation, Agent SID and enrolled launch scope, policy epoch, output/recipient/destination, use limit, monotonic expiry and nonce/controller audience. Caller text is not authoritative display data. Approval and execution must bind the same canonical transaction, with atomic consumption and a final scope check. The starting target is one use consumed within 60 seconds, as in Phase 3; it is not the currently implemented legacy five-minute grant.

**INFERENCE — Presence and recipient gaps.** A future native verifier must prove fresh human action and correct transaction binding, not merely a recent Main login or UI button result. No API is selected or claimed sufficient here. The independent C requirement in A08 is unchanged and remains INCOMPLETE. Main-only approval can be investigated as a narrower cross-account contract, not substituted for C in a full G2 claim. One Agent account provides whole-compartment scope; distinct process-only recipients remain unsupported. Main-context compromise remains outside this candidate's demonstrated protection while remaining a full-T gap.

**INFERENCE — Plaintext release stays disabled.** The chosen partial contract gives Agent public data and opaque references only. Future approved credential use occurs in a trusted Main helper for one operation; secret-bearing results/errors/logs remain private. Neither a general file-read endpoint nor arbitrary command execution under Main is allowed. No Main credential may become Agent environment or ambient helper authority. Raw disclosure to a networked Agent, or protected off-machine export, remains unavailable until separate consent, confinement, recipient and network prerequisites are satisfied. No public endpoint allowlist authorizes protected content by itself.

**INFERENCE — Policy.** Repository state contributes denies only. Authoritative policy, signing trust/key material, approved binaries and parents must be outside Agent write authority. Authorized relaxation originates in Main's independently opened console and commits one exact revision. Signing can detect an Agent-written revision but does not stop Main malware using Main keys, or establish the newest state after rollback. Independent W continuity and recovery remain unresolved. Missing/corrupt/older/unsupported policy must stop protected release; recreating a default permissive policy is not recovery.

**INFERENCE — Revocation.** Preserve Phase 3's serialized decision tD and complete-enforcement acknowledgement tA: no new protected operation/release commits after tD; queued requests and applicable helpers/network authorizations must stop or drain before REVOKED. The one-second target is unmeasured. Missed acknowledgement yields REVOCATION_PENDING/INCOMPLETE. Already committed disclosure cannot be recalled. Reference denial, ciphertext retention, backup deletion and downstream credential invalidation require distinct reporting.

## Per-account network contract: feasibility gate, not a finished mechanism

**INFERENCE — Candidate mechanism.** Evaluate administrator-owned, user-aware Windows Firewall/WFP enforcement for Agent's traffic and every descendant. Prefer a reviewed mechanism using existing OS enforcement without selecting a new driver. F10/F11 support identity-aware filtering as a mechanism; they do not prove a complete Windows Home configuration. Exact rule schema/product, management owner, signed deployment object and rollback remain **INCOMPLETE**. Agent's proxy settings, executable path, account creation or extension feature flags are not the enforcer.

**INFERENCE — Required semantics.** Agent traffic is denied unless its destination/transport operation is explicitly authorized; ordinary Main traffic is not silently placed under a new global policy. Main/management owns the enforcement state; Agent cannot modify or replace it. Policy must handle IPv4/IPv6, TCP/UDP/QUIC, DNS, alternate interfaces, direct IP, local services, proxies, redirects and helper/MCP delegation. Requests relayed through SYSTEM/Main services require their own authorization; matching only the identity of the final socket owner cannot be assumed to cover the requesting Agent.

**INFERENCE — Rule and outage pitfalls.** Do not assume an explicit Agent-wide block followed by a narrower allow forms a firewall allowlist: conflicting explicit blocks win [F11]. Do not assume dynamic-session objects survive a controller crash or that persistent objects establish boot-time coverage [F12]. Existing flows and policy refresh/revocation require observed enforcement. If mandatory account-scoped networking cannot be established, this model is not ready for a networked protection claim; no unrestricted fallback is permitted. Private custody stays private and protected release stays unavailable.

**INFERENCE — Scope limit.** Restricting Agent does not establish G4 for Main's unrestricted services, cloud synchronization or raw data intentionally delivered to Agent. The selected Hyper-V design also requires mandatory host enforcement, not guest filtering alone. Later loopback-only evidence can assess mediation and permission mechanics; it cannot certify off-machine egress or every interface.
