# G1–G6 mechanism matrix

**INFERENCE — Interpretation, 2026-10-09.** This matrix estimates contributions to the unchanged target, using the primary-source FACT entries R01–R33 in [research.md](research.md). Every assessment is INFERENCE, not an implementation or test result. A contribution is conditional on correct deployment and authority separation; none means that a mechanism alone establishes the corresponding guarantee.

## Working guarantee criteria

| Gate | Criterion derived from the supplied specification |
|---|---|
| G1 | **INFERENCE:** Marked assets and their reachable representations require default-deny access across every agent-controlled path. |
| G2 | **INFERENCE:** Access requires authenticated user-presence consent bound to item, operation, time and requester; agents cannot issue or widen it. |
| G3 | **INFERENCE:** Denial must survive lifecycle changes, policy tampering and loss of controller state, with fail-closed behavior. |
| G4 | **INFERENCE:** Mandatory OS/compartment egress allowlisting is separate from authorization to disclose protected bytes. |
| G5 | **INFERENCE:** Plaintext, decryption authority and secret-bearing copies must remain outside ungranted agent reach. |
| G6 | **INFERENCE:** Coverage claims require trustworthy effective-control evidence and explicit failures/unsupported states. |

## Composition rules and unresolved gates

**INFERENCE — Mandatory launch is insufficient if host authority remains.** A confined CLI does not cover an untrusted host extension, other same-user process, MCP server or remote helper that retains access to originals or policy. Candidate designs must either deny those identities access to protected assets or place all such components in the managed boundary. Treating them as trusted would change T.

**INFERENCE — Data granularity.** OS path/resource restrictions do not by themselves express protected text selections or arbitrary environment-key semantics. A trusted data boundary must produce an approved representation while keeping original buffers, histories, handles and keys inaccessible to untrusted readers.

**INFERENCE — Durability.** Pair confinement with protected asset/policy ownership and lifecycle-independent deny enforcement. A same-user deployment controller, permissive fallback launcher or repository-local authoritative deny list remains an unresolved G3 concern.

**INFERENCE — Approval and egress.** User presence, process identity and destination authorization are separate checks. A valid cryptographic signature, a local bearer token or an allowed network destination must not imply broader access than the transaction permits.

**INFERENCE — Status.** This survey supports candidate composition, not a PASS for any G1–G6 gate. Native-platform equivalence, historical editor versions and the requested real-agent matrix remain INCOMPLETE until appropriate later evidence exists.
